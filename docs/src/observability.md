# Observability

- **Structured logs** via the [`tracing`](https://crates.io/crates/tracing) crate, JSON output. Every request gets a server-generated id, which is the only id echoed (the `X-Request-Id` response header and internal-error bodies). A client-supplied `X-Request-Id` is never echoed; if it is ≤ 64 chars of `[A-Za-z0-9._-]` it is logged as `upstream_request_id` for correlation. Internal errors (GDAL, source I/O, cache backend) are logged in full with the request id, and clients receive only a generic message carrying that id. Each request gets a span carrying request id, protocol, layer, tile coords (when applicable), cache outcome (hit/miss/passthrough), source latency, and response status.
- **Prometheus metrics** at `/metrics` on a separate listener (`server.metrics_bind`, default `0.0.0.0:9091`; `null` disables it). Keep that port off the public network — scrape it from inside the cluster/host only. Metrics are: request counts and latencies (by protocol/layer/status), cache hit/miss/passthrough counters, hot-tier size and eviction counts, source pool wait time and checkout count, single-flight coalescing counts, error counts by class.
- **Health & readiness** endpoints: `/healthz` always returns 200 once the process is up; `/readyz` returns 200 only once config is parsed, source pools are warmed (at least one dataset open per source), and the cache backend is reachable.
- **No OpenTelemetry tracing in v1** — the tracing crate's structured spans are enough; OTLP export can be added later via `tracing-opentelemetry` without touching application code.
